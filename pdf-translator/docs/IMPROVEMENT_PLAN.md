## 2026-07-31(第3弾) 書籍・雑誌スキャン・議会報告書での鍛錬+セキュリティ最大化

**レイアウト/翻訳(検証素材: 書籍49頁・OCRスキャン雑誌・議会Research Briefing):**
- **リフローをユニット別フォントサイズに刷新**: ページ単一サイズを廃止し、各ユニットを
  原文ブロックサイズ×ページ係数で描画(見出し20pt/本文12pt/脚注9ptの階層を維持)。
  従来は最も窮屈な帯(脚注)がページ全体を床サイズまで縮小させていた。拡大(grow)は
  忠実性の観点から廃止。
- **欄外ユニットの原位置配置**: 本文帯と重ならない狭いブロック(書籍の欄外キャプション、
  表紙のサイドバー)は自身のbbox内で独立フロー(相互の重なりはtakenバンドで防止)。
- **幅が大きく異なる2レーンは独立フロー**(比0.7未満)。新聞式バランス流し込みは
  同幅段組のみ(表紙サイドバーとタイトルの混流を解消)。
- **レコード行の分離**: 数値セルが近接する行(目次の行・表の行)は1行=1ブロックで
  封印し、行単位の翻訳・配置に(目次が連結散文になる問題を解消)。
- **保持トークンの掃引ガード**: 断片掃引がTOCページ番号・表セルを削除しないよう、
  ページに残る要素のトークンを保護。
- **テキスト下線の障害物除外**: リンク下線(ブロックbbox内の罫線)を構造罫線と区別。
  リンクだらけの報告書でリフロー容量が崩壊する問題を解消。
- **繰り返しフッターのrunning_head化**(上端に加え下端も)+下端アンカーの余地確保。
- **脚注番号で終わる段落の文末判定**(「...area).4」)で段落連鎖を防止。
- **OCRスキャンPDFの明示拒否**: 全面画像+テキスト層のページが過半のPDFは
  「画像内の英語は消去不可能」と明確なメッセージで拒否(壊れた出力を出さない)。
- **空応答リトライ**: 無料エンジンが空を返したユニットを1回再試行。

**既知の制限(第3弾時点):**
- 書籍内の「項目名: 値」型の罫線キー表(Fearless諸元表など)は、行の封印+own-box配置で
  部分的に再現するが、セル欠落・位置ずれが残る(本格的な表構造検出は今後の課題)
- 無料エンジンの散発的な空応答(1回リトライ後も稀に未翻訳が残る → 該当段落は英語のまま保持)

**セキュリティ最大化(webapp/pipeline/Docker):**
- ジョブの実行時間上限(既定45分・`PDF_TRANSLATOR_JOB_TIMEOUT_MIN`)で暴走PDFをkill
- ページ数上限(既定300・`PDF_TRANSLATOR_MAX_PAGES`)でリソース枯渇を防止
- 変換系エンドポイントにIP別レート制限(既定30件/時・`PDF_TRANSLATOR_RATE_LIMIT`)
- 全応答にセキュリティヘッダ(CSP・X-Frame-Options DENY・nosniff・Referrer-Policy・
  Permissions-Policy・COOP/CORP)
- 認証失敗に250ms遅延(ブルートフォース抑制・asyncでイベントループ非ブロック)
- job_idのパス検証(^[0-9a-f]{12}$)
- Dockerコンテナを非rootユーザーで実行


## 2026-07-31(第2弾) 実文書2件(AW609パンフレット・RWUASプレスリリース)で判明した欠陥の根絶

- **Form XObject内テキストの除去**: InDesign系PDFは本文をXObject(Do)に格納するため
  従来の除去が素通りしていた(表紙ラベル・法務文が英語のまま残存)。
  `remove_text_by_content` をXObject再帰(深さ6・訪問済みガード・フォント継承)に拡張。
- **文字色の保持**: ブロックごとに塗り色を抽出し、オーバーレイを原文色で描画
  (白抜き文字が黒描画で不可視になる問題の解消)。Separation/DeviceN(スポットカラー)の
  tintはグレー誤読で白＝不可視になるため濃度(1-t)で近似(色相は不明のため黒系)。
- **数値マスキングの単語境界**: NUMパターンが「71 million」を「71 m」+「illion」に
  分断して訳文が壊れていた。単位の後に `(?![A-Za-z0-9])` を要求。
- **リフローの縦位置アンカー**: 各バンドは原文位置より上に始まらない
  (下部アンカーの脚注・下半分のセクションが上に吸い上がる問題の解消)。
- **リフローのサイズ忠実**: cap/growをページの原文本文サイズに追従
  (8ptのプレスリリースが15ptに膨張しない)。
- **写真主体文書の自動region化**: ページ面積の中央値30%以上が画像の文書は
  縦置きでもregionモード(AW609型パンフレットの見出し・段落が原位置に)。
- **「•」だけのブロックを障害物にしない**(リフロー/region両方。マーカーのy位置で
  フロー全体が分断される問題の解消)+文字を含まないブロックは翻訳対象外。
- **regionの水平クランプを保持ブロックにも適用**(表ラベル訳文が値セルに掛からない)。
- **保護パターン追加**: 裸ドメイン(leonardo.com)と普遍的な航空・技術略語
  (ISA/HIGE/HOGE/OEI等。「ひげ」「ホゲ」誤訳の防止)。
- 検証: AW101/AW609/RWUASの3実文書すべてgoogle無料エンジンで確認者1ラウンド合格、
  pytest 12件 green(数値境界・文字色の回帰テスト追加)。


## 2026-07-31 レイアウト忠実性の仕組み化(パンフレット/スライド品質の抜本改善)

実パンフレット(見開き・コールアウトラベル・仕様表・大型タイトル)で判明した
「配置が元PDFとずれる」問題を、サンプル特化なしの汎用ロジックで解消した。

- **M1を2次元セグメンテーションに刷新**: 文字→行は「縦重なり55%+横近接」で
  結合(離れた島は同じyでも絶対に混ざらない=文字交互化の根絶)。行→ブロックも
  「縦隣接+x重なり+フォントサイズ比≤1.25」で結合し、表の行(同じ行に複数セグ
  メント)は散文ブロックへ吸収しない。整列エッジ(他の行と共有される左端)への
  ギャップで行を分割し、島の融合を防止。回転文字(グラフ軸ラベル)は図扱いで除外。
- **仕様表の値列を `data` 判定**(数値+単位トークン比率)。値はそのまま保持され、
  ラベル列だけが翻訳される(表が連結散文として誤訳される問題の解消)。
- **M2の結合ゲート強化**: 横向きページでは幾何的に同一の島だけ結合。大文字始まり
  の弱い継続判定は本文長≥80文字時のみ。製品型番(AW101/CT7-8E等)は⟦Tn⟧保護。
- **M3(regionモード)の忠実配置**: フォントサイズを原文ブロックサイズに追従
  (39ptの表紙タイトルは表示サイズを維持、7ptラベルは小さいまま)。タイトル/見出し
  は原文の行数を維持(収まらなければ縮小)。巨大な障害物(写真)を飛び越えて下に
  流し込まない。縦に共存する領域同士は水平クランプで相互排他。罫線も障害物。
  元から写真上にあるテキストは押し下げない。
- **editorのモード自動判定**: 横向きページを含む文書に加え、縦でも「複数行段落が
  翻訳対象の過半に満たない」文書(ポスター/パンフレット)は region モードへ。
- **確認者(QA)に配置忠実性ゲートを追加**(仕組み化の核心):
  - regionモード: 各ユニットの描画位置が原文ブロック位置と一致(x±14pt/上方向
    -8〜+42pt)し、表示サイズ比0.55以上を機械検査(`layout_drift`/`size_fidelity`)。
  - reflowモード: 描画行がページの原文テキスト帯からはみ出さないことを検査。
  - 元から図上にあったテキストの図上描画は不適合にしない(背景写真上のラベル)。
- **回帰テスト**: `tests/test_layout_fidelity.py` が合成パンフレットPDFで
  島分離・表のdata判定・タイトルサイズ・配置一致・QA合格を恒久検証(10テスト green)。
- 実パンフレット(9頁見開き)が **google無料エンジン+ボタン1つで確認者を
  1ラウンド合格**。論文サンプルも reflow で合格を維持(golden更新済み)。


## 2026-07 再構築: 4ロール・アーキテクチャ + 実論文対応

参照ゴール(別システムの日英変換PDF)を1つの目標に設定し、役割分担型で再構築した。

**4ロール(`src/roles/`)** — 各ロールは単一の入口を持つモジュール、`orchestrator` が連結:
- **翻訳者 `translator_role`**: 英語→日本語(⟦Tn⟧保護・復元、参考文献は非翻訳)。無料Google既定、キーがあればClaude。
- **PDF製作者 `producer`**: PDF→レイアウト仕様(段組レーン・図表/保持テキストの障害物ボックス・読み順)。図表座標は原文のまま。
- **編集者 `editor`**: 図表を原位置に保ち、日本語を衝突なく配置(実証済みm3配置エンジンに委譲)。実描画行を `_placed.json` に出力。
- **確認者 `qa`**: 品質を保証し責任を持つ。①日本語妥当性(未翻訳ゼロ・⟦Tn⟧残存ゼロ・描画到達・残存英語≤閾値、任意でLLMの日本語自然性チェック)②配置忠実性(図保持・行/行&行/図の重なりゼロ・オーバーフローなし)を検査。**英語との意味照合はしない方針**。不適合時は各ロールに修正を要求し、フォント下限を下げる/再翻訳するなどして**最大N回自動リトライ**。
- **Web**: `webapp` は orchestrator をサブプロセス実行し、4ロールの進捗を日本語表示。

**実論文対応の本質的修正(サブセットフォント)**: pikepdf が返す生バイトはフォント固有コードで、pdfplumber の Unicode と一致しないため、内容ベースの英語除去が実論文で効かなかった。各フォントの **ToUnicode CMap でオペを Unicode 復号**してから照合するよう修正(`m3_generate._page_font_decoders` / `_decode_op`)。実ED論文(12頁)で残存英語 **147語→23語**、1頁目の要旨の英語透けが解消。合字グリフ ﬁ/ﬂ を引用符転用するフォント向けに展開版/除去版の二重正規化も追加。

**解決済み(この再構築で判明→修正)**:
- ~~一部ブロックで pdfplumber の文字抽出順序が崩れる~~ **修正済み**: 原因は `_cluster_rows` が行のバウンディングボックスを下方向に拡張し続け、行間の狭い箇所で連続する複数行(実ED論文で230文字=約4行)を1行に連鎖併合し、`_mkline` の x0 ソートで文字が交互化していたこと。行の基準を累積箱から**行中心の中央値(行内で安定)**に変更して連鎖を遮断。実ED論文2頁目の緒言が正常化し残存英語が解消。
